# CRWebPlayer — Standalone Build

This is the **complete, self-contained source** for the CRWebPlayer standalone build — a version of the Curious Reader book player that runs fully offline inside the Curious Reader React Native container app, loaded via a `file://` URI in a WebView.

Everything needed to build the engine and package books is in this repository. The only thing **not included** is `BookContent/` (≈150 directories of images and audio files totalling several GB) — you bring that from your asset store, and the build scripts handle the rest.

## Overview

The standard CRWebPlayer loads book content over HTTPS and uses a service worker to cache it. That approach does not work when the app is launched from a `file://` URI (e.g. extracted assets on device storage) because:

- `fetch()` fails on `file://`
- `Cache API` / `caches.open()` fails on `file://`
- Service workers cannot be registered from `file://`
- Absolute URL construction (`window.location.origin + path`) produces invalid paths

This standalone build solves all of those problems. It produces three independently downloadable ZIPs per language edition of each book. The container app downloads whichever ZIPs the user needs, extracts them into the same directory, and opens `index.html`.

## Prerequisites

| Tool | Minimum version | Notes |
|------|----------------|-------|
| Node.js | 18 LTS | `node --version` |
| npm | 8 | Comes with Node 18 |
| Git | any | For the initial clone |
| ffmpeg + ffprobe | 4.x | Audio re-encode (Opus 24 kbps mono) — `brew install ffmpeg` |
| cwebp | 1.x | Image re-encode (WebP q80) — `brew install webp` |

> **Why ffmpeg and cwebp?** The build scripts re-encode narration audio and illustrations into modern, smaller formats (Opus + WebP) on the way into each ZIP. This shrinks the per-language ZIPs by roughly 60–70% and the per-book ZIPs by roughly 30–50% with no perceptible quality change. Audio duration is verified to within ±5 ms after every conversion so word-by-word highlighting stays in sync. Source content in `BookContent/` is never modified. See [Shrinking the payload](#shrinking-the-payload) below for details.

## Initial setup

### 0. Verify you have the right package.json (quick sanity check)

Before running anything, confirm the `package.json` in your repo root looks correct:

```bash
grep '"name"' package.json
# Should print:  "name": "crwebplayer-standalone",
# If it prints:  "name": "workspace",  — you have the wrong file. See Troubleshooting below.
```

---

### 1. Clone this repository

```bash
git clone https://github.com/tinsleygalyean/CRWebPlayer-standalone.git
cd CRWebPlayer-standalone
```

### 2. Bring in BookContent assets

`BookContent/` contains the raw book content (illustrations and audio files) for all ≈150 book+language editions. It is not committed to this repo due to size.

**Option A — copy from the original CRWebPlayer repo:**

```bash
# From inside your CRWebPlayer-standalone checkout:
git clone --depth 1 https://github.com/curiouslearning/CRWebPlayer.git /tmp/crwp-source

# Use rsync (not cp -r) to skip 3 known case-collision duplicates.
# macOS's default filesystem is case-insensitive, so directories that differ
# only in case (e.g. "Isizulu" vs "IsiZulu") collide on Mac. The catalog in
# scripts/lib/content-catalog.js already marks these as duplicates, so we
# skip the duplicate variants entirely.
rsync -a \
  --exclude='MyFirstDayAtTheMarketIsizulu' \
  --exclude='HideAndSeekLevel4En' \
  --exclude='TallAndShortUkrLv6' \
  /tmp/crwp-source/BookContent/ ./BookContent/
```

> If you see `cp: cannot create directory ... File exists` or a list of `wordfile-*.mp3 already exists` errors, you used `cp -r` instead of `rsync` — see [Troubleshooting — duplicate BookContent dirs on macOS](#duplicate-bookcontent-dirs-on-macos) below.

**Option B — restore from your internal asset store / S3 / shared drive:**

Place the directory so the structure looks like:

```
CRWebPlayer-standalone/
└── BookContent/
    ├── TheLionRunsAndTheCowWalksSwahili/
    │   └── content/
    │       ├── content.json
    │       ├── images/
    │       └── audios/
    ├── LetsFlyLevel2En/
    │   └── content/
    │       └── …
    └── … (≈150 more directories)
```

Each directory must contain a `content/` subdirectory with at minimum `content.json`. The `images/` and `audios/` subdirectories are required to produce usable ZIPs.

### 3. Install dependencies

```bash
# Node dependencies
npm install

# Native tools used by the build scripts (audio + image re-encode).
# macOS:
brew install ffmpeg webp
# Debian / Ubuntu:
sudo apt install ffmpeg webp
```

This installs all packages listed in `package.json`, including:

- `webpack` / `ts-loader` / `typescript` — TypeScript compilation
- `html-webpack-plugin` — injects `crwebplayer.js` into `index.html`
- `jszip` — ZIP creation in the build scripts
- `@splidejs/splide` — slide-carousel (bundled locally, not from CDN)
- `firebase` / `workbox-window` — analytics and service-worker client

No other setup is needed — all engine-level static assets (fonts, loading images, Splide CSS/JS) are already committed to `dist/`.

> **If `npm install` fails with "Use pnpm instead"** — see [Troubleshooting — wrong package.json](#wrong-packagejson-in-repo-root) below.

## How the ZIPs work

Three ZIPs, extracted in order into the **same directory**, produce a complete playable book:

```
crwp-core.zip               ← engine runtime (one per app release)
crwp-book-<bookslug>.zip    ← illustrations and book metadata (one per book)
crwp-book-<bookslug>-lang-<langcode>.zip  ← text, audio, fonts (one per language edition)
```

Resulting directory layout after extraction:

```
index.html
crwebplayer.js
assets/
  splide4.min.css
  splide4.min.js
  fonts/Quicksand_Bold.otf
  images/loadingImg.gif
books/
  <bookslug>/
    book.json
    images/            ← from the book ZIP
    lang/
      <langcode>/
        text.json      ← the book's content.json, from the language ZIP
        audios/        ← narration audio, from the language ZIP
        fonts/         ← optional per-language fonts, from the language ZIP
        lang.json      ← language metadata, from the language ZIP
```

No file is duplicated across ZIPs — the build checks enforce this.

## Building — step by step

All commands are run from the repository root.

### Step 1 — Build the engine ZIP

The engine ZIP contains the compiled JavaScript bundle and all engine-level static assets (loading screen, fonts, Splide). It does **not** contain any book content.

```bash
npm run build:engine
# or equivalently:
node scripts/build-engine.js
```

**What it does:**

1. Runs `webpack` with `webpack.standalone.config.js`
   - Compiles `src/standalone/standalone-entry.ts` → `crwebplayer.js`
   - `publicPath` is set to `./` so all asset references are relative
   - `STANDALONE=true` is baked in via `DefinePlugin`
   - Source maps are disabled
2. Copies engine-level static assets from `dist/` and `node_modules/` into the ZIP
3. Runs §4a build-time checks (no absolute paths, no external scripts, no source maps)
4. Writes `dist/standalone/crwp-core.zip`

**Output:**

```
dist/standalone/crwp-core.zip
```

**Rebuild the engine whenever you:**
- Change any TypeScript source file
- Change `index.standalone.html`
- Update engine-level static assets (fonts, loading image)

---

### Step 2 — Build a book ZIP

The book ZIP contains the shared illustrations for one book (all language editions of a book share the same illustrations).

```bash
npm run build:book -- <bookslug>
# or equivalently:
node scripts/build-book.js <bookslug>
```

Replace `<bookslug>` with one of the stable book identifiers. Examples:

```bash
node scripts/build-book.js the-lion-runs-and-the-cow-walks
node scripts/build-book.js lets-fly
node scripts/build-book.js tall-and-short
```

See [book slug reference](#book-slug-reference) for all valid slugs.

**What it does:**

1. Looks up all source `BookContent/` directories for this book in the content catalog
2. Copies `images/` from the first (canonical) language variant into `books/<bookslug>/images/`
3. Warns if image counts differ across language variants
4. Generates `books/<bookslug>/book.json` with page count and language list
5. Writes `dist/standalone/crwp-book-<bookslug>.zip`

**Output:**

```
dist/standalone/crwp-book-<bookslug>.zip
```

---

### Step 3 — Build a language ZIP

The language ZIP contains everything specific to one language edition: the content JSON (page layout + text), narration audio, and any per-language fonts.

```bash
npm run build:lang -- <bookslug> <langcode>
# or equivalently:
node scripts/build-lang.js <bookslug> <langcode>
```

Examples:

```bash
node scripts/build-lang.js the-lion-runs-and-the-cow-walks swahili
node scripts/build-lang.js lets-fly hindi
node scripts/build-lang.js tall-and-short ukrainian
```

**What it does:**

1. Looks up the source `BookContent/` directory for this `(bookslug, langcode)` pair
2. Copies `content.json` → `books/<bookslug>/lang/<langcode>/text.json`
3. Copies `audios/` → `books/<bookslug>/lang/<langcode>/audios/`
4. Copies `fonts/` (if present) → `books/<bookslug>/lang/<langcode>/fonts/`
5. Generates `books/<bookslug>/lang/<langcode>/lang.json` with display names and estimated audio duration
6. Writes `dist/standalone/crwp-book-<bookslug>-lang-<langcode>.zip`

**Output:**

```
dist/standalone/crwp-book-<bookslug>-lang-<langcode>.zip
```

---

### Step 4 — Build everything at once

To build all 193 ZIPs (1 engine + 25 books + 167 language editions) in a single run:

```bash
npm run build:standalone
# or equivalently:
node scripts/build-all-standalone.js
```

**Useful flags:**

```bash
# Skip the webpack step (useful if you only changed BookContent assets)
node scripts/build-all-standalone.js --skip-engine

# Build only one book and all its languages
node scripts/build-all-standalone.js --book the-lion-runs-and-the-cow-walks
```

**What it does, in order:**

1. Builds the engine ZIP (step 1)
2. Builds every book ZIP (step 2) in catalog order
3. Builds every language ZIP (step 3) in catalog order
4. Runs §4a ZIP-overlap checks across a sample of (engine, book, language) triples
5. Writes `dist/standalone/manifest.csv` — filename, type, bookSlug, langCode, size, sha256
6. Writes `dist/standalone/README.md` — build date, commit, book/language table

**Expected output:**

```
dist/standalone/
├── crwp-core.zip
├── crwp-book-the-bee-and-the-elephant.zip
├── crwp-book-the-bee-and-the-elephant-lang-english.zip
├── crwp-book-the-bee-and-the-elephant-lang-hindi.zip
│   … (193 ZIPs total)
├── manifest.csv
└── README.md
```

## Adding a new book or language

1. Add the `BookContent/<DirName>/content/` directory as normal.

2. Open `scripts/lib/content-catalog.js` and add a new entry to the `CATALOG` array:

   ```js
   { dir: 'MyNewBookSwahili', bookSlug: 'my-new-book', langCode: 'swahili' },
   ```

   - `dir` — the exact `BookContent/` directory name
   - `bookSlug` — lowercase, dashes only, **stable forever** (renaming orphans on-device caches)
   - `langCode` — must match the code used in `languages.json` in the container app

3. Run the catalog validator to check for collisions:

   ```bash
   node -e "
   const c = require('./scripts/lib/content-catalog.js');
   const w = c.validateCatalog();
   console.log(w.length ? w : 'No collisions found.');
   "
   ```

4. Build the new ZIPs:

   ```bash
   node scripts/build-book.js my-new-book
   node scripts/build-lang.js my-new-book swahili
   ```

## Compliance notes

All offline compatibility requirements from `STANDALONE-NOTES.md` are met:

- **§2a** — Firebase init is wrapped in `Promise.race` with a 5-second timeout
- **§2c** — Service worker is never registered on `file://`
- **§2d** — webpack `publicPath: './'`; all asset paths are relative
- **§2e** — No `window.location.origin` in any asset URL
- **§2f** — All analytics calls are fire-and-forget (`try/catch`, no `await`)
- **§2g** — `loadBinary()` uses XHR on `file://`, `fetch` on `https://`
- **§5d** — `STANDALONE=true` baked in via `DefinePlugin`
- **§8** — `index.html` has no external `<script>` tags; Splide is bundled locally

See `STANDALONE-NOTES.md` for the full compliance table and outstanding items for the container team.

## Shrinking the payload

Every audio and image file is re-encoded at build time before being added to the ZIP:

| Source format | Output format | How |
|---|---|---|
| `.mp3` / `.wav` / `.ogg` / `.m4a` / `.aac` / `.flac` | **Opus 24 kbps mono in `.webm`** | `ffmpeg -c:a libopus -b:a 24k -ac 1 -vbr on -application voip` |
| `.jpg` / `.jpeg` / `.png` | **WebP quality 80** | `cwebp -q 80 -m 6` |
| `.webm` / `.opus` / `.webp` | passthrough | already in target format |
| fonts, JSON, everything else | passthrough | not re-encoded |

The audio extension inside the ZIP is `.webm`, not `.opus`, because `<audio>` element compatibility for WebM/Opus is broader than for raw `.opus` files (iOS WKWebView ≥ 17.4, all modern Android WebView, every desktop browser).

### Audio encoding default (iOS-safe)

`scripts/build-all-standalone.js` **defaults** to AAC-HE 32 kbps mono in `.m4a` containers. AAC-HE plays natively on every iOS version the Curious Reader container currently supports (iOS 11+), so the default build is safe to ship to the full install base. Output is roughly 25% larger than Opus 24 kbps but still a large reduction versus the original MP3s.

Per-script builds (`build-book.js` / `build-lang.js`) read `USE_M4A_FALLBACK` directly from the environment and have **no default** — they encode whatever you ask for. Use `build-all-standalone.js` if you want the iOS-safe default applied automatically.

### Opting in to Opus (smaller, iOS ≥ 17.4 only)

Once your iOS support floor is 17.4 or newer, switch to Opus 24 kbps mono in `.webm`:

```bash
node scripts/build-all-standalone.js --opus
# equivalent:
USE_M4A_FALLBACK=0 node scripts/build-all-standalone.js
```

Opus produces roughly 25% smaller language ZIPs than the AAC-HE default. Safari/WebKit only added Opus-in-WebM playback in `<audio>` in iOS 17.4 (March 2024), so anything older falls back to silence — keep the default unless you've confirmed your install base.

### Codec / container support summary

| Encoder | Container | iOS WKWebView `<audio>` | Android WebView | Desktop browsers |
|---|---|---|---|---|
| AAC-HE 32 kbps mono **(default)** | `.m4a` | iOS 11+ | 5.0+ | All current |
| Opus 24 kbps mono (`--opus`) | `.webm` | **iOS 17.4+ only** | 5.0+ | All current |
| WebP q80 (images) | `.webp` | iOS 14+ | 4.4+ | All current |

### Word-by-word highlight sync

The player synchronizes word highlighting using per-word `start`/`end` timestamps (in seconds) stored in `content.json` and queried against `<audio>.currentTime`. To make sure re-encoding doesn't shift those timings, every audio conversion is verified with `ffprobe` and the build is **aborted with a clear error** if input and output duration differ by more than 50 ms. The ffmpeg invocation also deliberately omits every flag that could change duration — no `-ss`, no `-t`, no filters, no resampling.

Numeric timing values inside `content.json` are never modified. Only string values whose extension matches a known media format (`.mp3` → `.webm`, `.jpg` → `.webp`) are rewritten.

### Cache

Converted files are cached at `dist/.asset-cache/<sha256>.<ext>` and re-used on subsequent builds. Re-encoding a fresh BookContent tree takes a while (minutes for a full `build:standalone` run); subsequent builds are near-instant for any file whose source hasn't changed. Delete the cache directory to force a full re-encode.

```bash
rm -rf dist/.asset-cache
```

## Troubleshooting

### `Source directory not found: BookContent/<Dir>/content/`

The build script cannot find the BookContent assets. Make sure `BookContent/` is checked out and present at the repository root. See [Initial setup — step 2](#2-restore-bookcontent-assets).

### `webpack: Module not found: Error: Can't resolve '…'`

Run `npm install` again. If the error names a TypeScript source file, make sure you have the full source tree checked out (not just the standalone additions).

### `crwp-core.zip` opens to a blank screen

Open the browser console. Common causes:
- An asset path is still absolute — check `webpack.standalone.config.js` for `publicPath: './'`
- `crwebplayer.js` was not found — make sure you extracted `crwp-core.zip` before opening `index.html`
- The book/language ZIPs were not extracted into the same directory as `index.html`

### Firebase console shows no events from offline playback

This is expected. Firebase Analytics requires an internet connection to send events. Events are logged in memory during offline play; some SDKs will retry when connectivity resumes. This does not affect playback.

### `§4a FAIL: ZIP-to-ZIP overlap`

Two ZIPs contain the same file path. This usually means a static asset was added to both the engine and book build configs. Check `ENGINE_STATIC_ASSETS` in `scripts/build-engine.js` and the directory structure produced by `scripts/build-book.js`.

### Build succeeds but audio does not play on Android

Ensure audio files are `.mp3` (not `.wav`) — some Android WebViews do not support WAV. If the source `audios/` directory contains WAV files, convert them before building the language ZIPs.

### Duplicate BookContent dirs on macOS

**Symptom:** running `cp -r /tmp/crwp-source/BookContent ./BookContent` produces hundreds of errors like:

```
cp: 'BookContent/MyFirstDayAtTheMarketIsizulu/content/audios/wordfile-…mp3'
    and '/tmp/crwp-source/BookContent/MyFirstDayAtTheMarketIsiZulu/content/audios/wordfile-…mp3'
    are the same file
```

**Cause:** the upstream CRWebPlayer repo contains three directory pairs that differ only in letter case:

| Kept (canonical)                       | Skipped (duplicate)                    |
| -------------------------------------- | -------------------------------------- |
| `MyFirstDayAtTheMarketIsiZulu`         | `MyFirstDayAtTheMarketIsizulu`         |
| `HideAndSeekIsiZuluLv4` (+ others)     | `HideAndSeekLevel4En` (English copy)   |
| `TallAndShortIsiZuluLv4` (+ others)    | `TallAndShortUkrLv6` (Ukrainian copy)  |

macOS's default APFS filesystem is case-**insensitive**, so the second member of each pair collides with the first during `cp -r`. The catalog in `scripts/lib/content-catalog.js` already marks the duplicates with `duplicate: true` and the build scripts ignore them — so you can simply skip them at copy time.

**Fix:** use `rsync` with explicit excludes instead of `cp -r`:

```bash
rsync -a \
  --exclude='MyFirstDayAtTheMarketIsizulu' \
  --exclude='HideAndSeekLevel4En' \
  --exclude='TallAndShortUkrLv6' \
  /tmp/crwp-source/BookContent/ ./BookContent/
```

If `BookContent/` already exists in a partially-copied state, delete it first:

```bash
rm -rf ./BookContent
# then re-run the rsync above
```

This issue does not occur on Linux (which is case-sensitive), so CI builds and the Replit build environment are unaffected.

### Wrong `package.json` in repo root

**Symptom:**
```
> workspace@0.0.0 preinstall
npm error Use pnpm instead
```

**Cause:** The Replit development environment that produced this repo is a pnpm monorepo whose *root* `package.json` (name: `workspace`, version: `0.0.0`) enforces pnpm and blocks npm. If that root file ends up at the top level of your clone instead of the correct `crwebplayer-standalone` one, you get this error.

**Immediate fix** — replace the file in your local clone:

```bash
# From the root of your local CRWebPlayer-standalone clone:
curl -o package.json https://raw.githubusercontent.com/tinsleygalyean/CRWebPlayer-standalone/main/package.json

# Verify it now says crwebplayer-standalone:
grep '"name"' package.json
# "name": "crwebplayer-standalone",

# Then install:
npm install
```

**Or fix it manually** — open `package.json` in a text editor, delete the entire file, and paste:

```json
{
  "name": "crwebplayer-standalone",
  "version": "1.0.0",
```

**How to prevent it when pushing to a new repo:** always push from *inside* the `CRWebPlayer/` subdirectory, not from the Replit workspace root:

```bash
# ✓ Correct — push from the CRWebPlayer subdirectory
cd /path/to/replit-workspace/CRWebPlayer
git init
git remote add origin https://github.com/tinsleygalyean/CRWebPlayer-standalone.git
git add .
git commit -m "initial standalone build"

# ✗ Wrong — pushing from the workspace root includes the pnpm enforcement package.json
cd /path/to/replit-workspace
git push ...   # this commits the root package.json alongside everything else
```
